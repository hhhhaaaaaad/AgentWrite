# Interview Sprint

Use this guide when the user selects interview preparation, supplies a job description, requests mock questioning, or asks for interview artifacts.

## Gap Map

Map the job or target interview to evidence:

| Capability | Importance | Current evidence | Gap | Verification |
|---|---:|---|---|---|

Allocate time from interview likelihood, current ratings, prerequisite value, and evidence gaps. Preserve separately reserved algorithm time.

## Answer Pattern

For project follow-ups:

```text
direct conclusion
-> what I actually did
-> mechanism and tradeoff
-> evidence
-> limitation and next step
```

Keep first answers within the selected detail level; expand after follow-up. Distinguish implemented, tested, observed, designed, and not practiced.

For coding questions, use C++ ACM input/output unless specified otherwise. Prefer C++14-compatible syntax so the code also compiles under C++17/C++20. Give runnable code, complexity, and key boundaries.

## Optional Artifacts

Generate only those explicitly selected:

- 30-second, 90-second, or 2-3 minute introduction;
- high-frequency follow-up bank;
- fact-checked knowledge base;
- mock-interview prompt;
- job-to-project migration answer;
- source coverage audit.

Do not invent candidate facts or metrics. General knowledge may supplement theory but must be separated from personal experience.
