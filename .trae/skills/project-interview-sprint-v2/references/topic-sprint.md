# Topic Sprint

Use this guide for one technology or tightly scoped knowledge point.

## Plan

Build blocks from the confirmed outcome:

1. prerequisite check;
2. core mental model;
3. mechanism and boundaries;
4. selected practice;
5. transfer question;
6. compact acceptance.

Allow 100% of the time to stay on the topic. Do not inject backend, infra, algorithms, or interview content unless selected or required by the topic.

## Interaction

- Begin with a short diagnostic question after configuration is confirmed.
- Teach only the missing layer revealed by the answer.
- Map to a project only when the user supplied one or selected application as a goal.
- If practice is `theory only`, use examples or pseudocode without editing files.
- If practice is `inspect`, trace the smallest relevant implementation path.
- If practice is `hands-on`, define an observable acceptance check before coding.

## Acceptance

End when the learner can explain the concept, answer a variant, and identify a failure case. Add an implementation or experiment check only when selected.

Default artifact: one deduplicated knowledge card. Do not produce interview scripts unless interview is a selected goal.
