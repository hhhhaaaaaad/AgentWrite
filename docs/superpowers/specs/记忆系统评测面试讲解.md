## 〇、评测的核心挑战 + 一句话定位

记忆系统评测比普通 CRUD 系统难，因为一个根本问题：

> **质量损失可能发生在五个互不重叠的阶段（抽取 / 检索 / 一致性 / 注入 / 治理），如果只测"最终回答好不好"，无法定位是抽错、检索漏、还是注入乱。**

**一句话定位**：

> "我把记忆系统质量拆成**五个可归因维度**，每维独立算指标，能回答'到底是哪个阶段出了问题'；再套一个**三层闭环**（离线定基线 → 在线监控熔断 → 实时纠错反哺），让系统越用越准。"

## 一、五维可归因评测（怎么拆解"质量"）

### 1.1 为什么拆五维（「可归因」是灵魂）

记忆系统的质量损失不在一个地方，拆成五维，每维对应一个阶段、各自独立算指标：

| 维度 | 对应阶段 | 回答的问题 | 核心指标 |
|---|---|---|---|
| ① 抽取质量 | 抽取 | 该不该存 | Precision / Recall / 错误归属率 |
| ② 检索质量 | 检索 | 能不能检索出来 | Recall@K / MRR / NDCG |
| ③ 一致性 | 存储 + 治理 | 记忆变乱没 | 重复率 / 冲突率 / 一致率 |
| ④ 注入质量 | 注入 | 组装合理不 | 无关注入率 / 成对胜率 |
| ⑤ 治理质量 | 治理 | 关联合理不 | 误合并率 / 错误隔离率 |

**关键洞察（面试必讲）**：五维独立的目的是「**可归因**」——维度② Recall@K 低，就说明是检索漏了、不是抽取错。这比"效果不好"这种笼统说法高一个层次。

### 1.2 每维怎么算（具体例子）

**维度① 抽取质量**：构造对话，人工标注"该抽出哪些记忆"（ground-truth），跑抽取对比。

- Precision = 抽对 / 抽出总数（抽了多少垃圾）
- Recall = 抽对 / ground-truth 总数（漏抽了多少）

> 例子：对话"我们项目用 Java 17"，ground-truth 标注"技术栈 Java 17"。若 LLM 抽出"技术栈 Java 17" + "用户喜欢 Java"，那 Precision = 1/2（"喜欢 Java"是过度引申、抽错了），Recall = 1/1。

**维度② 检索质量**：构造 query，标注"该召回哪些记忆 id"。

- Recall@5 = top-5 里命中 ground-truth 的比例

> 例子：query = "写一篇 JVM 文章"，ground-truth 是"技术栈 Java 17"这条记忆。若检索 top-5 里有它，Recall 命中。

### 1.3 面试追问 + 答法

**Q：为什么拆五维，不直接看最终回答质量？**
> "因为最终回答质量是五个阶段的叠加，拆不开就不知道改哪。五维独立算，才能'可归因'——Recall@K 低是检索问题，Precision 低是抽取问题，无关注入率高是注入问题。评测的目的不是'打分'，是'定位'。"

**Q：指标这么多，怎么保证能落地？**
> "每个维度就两三个核心指标，不是铺一堆。而且评测集脚本化（`EvaluationRunner`），跑一次出五维报告，不用人工算。"

## 二、黄金评测集怎么建

### 2.1 两类评测集 + 覆盖矩阵

| 评测集 | 形态 | 用于 |
|---|---|---|
| 对话→记忆对 | 一段对话 + 标注"该抽出哪些记忆" | ① 抽取质量 |
| query→记忆对 | 一个 query + 标注"该召回哪些记忆 id" | ② 检索、④ 注入 |

**覆盖矩阵**：必须覆盖 **4 种记忆类型 × 6 类边界 case**，否则指标虚高：

| 边界 case | 测什么 |
|---|---|
| 相似但不同 | 身份化不误合并 |
| 同义重复 | 去重 |
| 时间演化 | 版本化演进 |
| AI 输出冒充用户 | 归属隔离 |
| 一次性指令 | 低价值过滤 |
| 跨会话碎片 | 跨会话关联 |

### 2.2 隔离原则（防指标虚高）

1. **评测样本不进 Prompt Few-shot**——否则测的是"背题"、不是泛化。
2. **调参集和报指标集分开**——防过拟合。
3. **同一黄金集回归**——改 Prompt/阈值后在同一集上重跑，才能比"有提升还是无回归"。

### 2.3 面试追问 + 答法

**Q：评测集从哪来？规模多大？**
> "两条来源：真实对话脱敏 + 人工构造边界 case（边界 case 必须人工构造，真实对话里稀疏）。起步规模 query→记忆对 ≥200、对话→记忆对 ≥50。上线后用户纠错样本经人工复核自动归档进评测集，持续扩充——这就是'数据飞轮'的评测侧。"

**Q：评测集会不会本身有偏？**
> "会，所以有三条防偏：样本不进 Few-shot（防背题）、调参集和报指标集分开（防过拟合）、边界 case 人工覆盖（防真实对话的稀疏性）。评测集本身也要版本化，才能跨改动对比。"

## 三、三层质量闭环（怎么持续保证质量）

```
① 离线评测（静态测试集）  → 定基线、调阈值
② 实时监控 + 熔断         → 发现异常、及时止血
③ 实时纠错 + 反哺         → 定位错误、越用越准
```

### 3.1 第①层：离线评测（定基线）

上线前用黄金集跑出具体数字，承担**三个不可替代的角色**：

| 角色 | 具体做法 | 例子 |
|---|---|---|
| **定基线** | 改造前跑出 Recall@5 / MRR / 抽取 P/R | 改造前 Recall@5=0.62、抽取 Precision=0.81 |
| **调阈值** | 改 RRF_K、α/β boost、余弦 0.9 等，看指标有没有变好 | RRF_K 从 60→100，Recall@5 从 0.62→0.65 → 采用 |
| **守护回归** | 每次改 Prompt/公式/阈值，同一黄金集重跑 | 改抽取 Prompt 后 Precision 0.81→0.79 → 回退 |

**一句话讲法**：「离线评测回答'这个改动有没有提升、有没有回归'——它是所有线上改动的'试金石'，上线前先在这过关。」

### 3.2 第②层：实时监控 + 熔断（发现异常）

上线后埋三类指标，异常超阈值就熔断关闭注入：

| 指标 | 阈值（初始） | 超阈值动作 |
|---|---|---|
| 抽取驳回率 `reject_rate` | > 20% 连续 15 分钟 | 熔断（抽取规则异常） |
| 向量同步积压 `pending` | > 500 且持续上升 | 熔断（补偿任务失效） |
| Qdrant 写失败率 | 5 分钟超阈值 | 熔断（向量库故障） |
| 核心事实一致性错误率 | > 3% 抽检批次 | P0 告警 |

**熔断降级分三级**（由轻到重）：

1. **一级**：关闭记忆注入（`retrieveContext` 返回空，Agent 退化无记忆模式）
2. **二级**：暂停结构化写入，仅归档原始对话片段
3. **三级**：人工介入告警

**恢复**：抽样准确率 > 95% 才灰度放量（10% → 50% → 100%）。

**先埋点后调阈值**：首月只对 4 个核心指标告警（写失败率 / 积压 / 抽取 accept/reject），其余指标只记录不告警，基线收集后再定阈值。

**一句话讲法**：「在线监控回答'线上现在有没有异常、要不要止血'——宁可没有记忆、不能用错记忆。」

**指标的双重用途**（面试加分点）：

```
指标异常 ──┬── ① 触发熔断（防守：写失败率/积压/驳回率超阈值 → 关闭注入）
           └── ② 驱动反哺（进攻：重复率/冲突率上升 → 定位根因 → 反哺 Prompt/阈值）
```

同一个指标，既是熔断的扳机、又是反哺的输入——避免"只告警、不改进"的死循环。

### 3.3 第③层：实时纠错 + 反哺（越用越准）

**四层信号检测**（从强到弱，判断"这条记忆是不是错的"）：

| 层 | 信号 | 可靠度 | 处理 |
|---|---|---|---|
| ① 用户显式否定 | "你记错了 / 不对 / 我不用 X 了" | 最强（用户是权威） | 立即隔离 + 写正确值 |
| ② 内部一致性冲突 | 同 subject 异 value（"研二" vs "已毕业"） | 强（至少一个错） | 标 DISPUTED 等裁决 |
| ③ 证据回溯失败 | evidence 撑不起 content | 中（疑似幻觉） | 标 QUARANTINED 软隔离 |
| ④ 统计异常 | 低置信高频注入 / 驳回率飙升 | 弱（整体质量差） | 降权 / 熔断，不隔离单条 |

**关键边界**：系统能"发现疑似"（矛盾 / 无证据），但不能"确定对错"（需外部真相），所以「能确定才隔离、疑似只标待确认」。

**反哺三方向 + 根因映射**（错误样本 → 根因分类 → 定向反哺）：

| 根因 | 反哺到哪 |
|---|---|
| 幻觉（无证据） | 抽取 Prompt（要求 evidence 强校验） |
| 过度引申（有证据但撑不起） | 阈值（收紧置信度门槛） |
| 归属错误（AI 冒充用户） | 规则（attributed_to 隔离） |
| 过期失效（曾经对现在错） | 生命周期（过期策略） |

**反哺闭环度量**：反哺后回归看错误数下降、Precision/Recall 提升、无关注入率下降，没改善说明根因分类错了、需重新定位。

**一句话讲法**：「实时纠错回答'这条记忆是不是错的'，反哺回答'错误怎么变成下一次的准确'——数据飞轮，越用越准。」

### 3.4 面试追问 + 答法

**Q：监控指标怎么设计？**
> "三类指标：链路指标（延迟/失败率，定位哪慢了）、质量指标（驳回率/重复率，定位哪错了）、错误专项（带根因分类，驱动反哺）。指标有双重用途——既是熔断的扳机，又是反哺的输入。"

**Q：反哺怎么做，怎么知道生效？**
> "错误样本带根因分类，根因决定反哺方向。反哺后闭环度量——错误数下降、Precision/Recall 提升、无关注入率下降，没改善说明根因分类错了、需重新定位。这就是 PDCA 的 Check/Act 环节。"

## 四、根本边界（无法 100% 自主判对错）

**记忆系统「自主判断内容对错」本质需要外部 ground-truth，而系统没有**——它只有"用户告诉过它的东西"，没有"真相"。

所以策略是「分层检测疑似 + 保守处理」：能确定的隔离、疑似的标待确认、最终靠用户裁决。

> **宁可不删、不可删错。** 这是记忆系统区别于普通 CRUD 系统的本质——它存的是「信念」（用户说过什么），不是「事实」（真相对错）。

**面试加分点**：主动承认这个边界，比吹"我的系统能自动纠错"高明得多——它体现你对「AI 记忆的本质局限」的清醒认知。

## 附：面试完整串讲（3 分钟脚本）+ 追问速查

### 完整串讲脚本

> "我评测记忆系统分两步。第一步是**五维可归因评测**——把质量拆成抽取/检索/一致性/注入/治理五个独立维度，每维算自己的指标，能定位'到底是抽错、检索漏、还是注入乱'，而不是笼统说效果不好。基础是黄金评测集，覆盖 4 种记忆类型 × 6 类边界 case，且评测样本不进 Prompt Few-shot 防虚高。
>
> 第二步是**三层质量闭环**——离线评测定基线、在线监控熔断发现异常止血、实时纠错反哺让系统越用越准。
>
> 最后我诚实说一个边界：记忆系统无法 100% 自主判断事实对错，因为没有外部真相，所以是'分层检测疑似 + 保守处理'，宁可不删、不可删错。"

### 追问速查

| 追问 | 一句话答案 |
|---|---|
| 为什么拆五维？ | 可归因——定位问题在哪个阶段 |
| 评测集怎么防虚高？ | 样本不进 Few-shot + 调参集报指标集分开 |
| 监控指标怎么设计？ | 三类（链路/质量/错误专项）+ 双重用途（熔断 + 反哺） |
| 反哺怎么生效？ | 根因分类定方向 + 闭环度量验证 |
| 能自主判错吗？ | 不能，无外部真相，分层检测疑似 + 保守处理 |
