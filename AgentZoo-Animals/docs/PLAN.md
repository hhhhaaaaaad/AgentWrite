# 赛博动物园 · 技术方案（v1）

> 状态：方案已冻结待实施。本文档为单一事实来源（Single Source of Truth），代码按本方案分期落地。
> 未敲定项见文末「待敲定」一节。

---

## 0. 一句话定位

一个**桌面端多智能体动物园**：每只动物都是一个负责真实任务的 AI Agent，住在一个俯视 2D 动物园里，会自己走动、干活、串门、吐槽。**任务为主，社交为皮，抽象当道。**

---

## 1. 产品形态

Electron 桌面客户端。打开是一张**俯视 2D 动物园地图**（模拟经营视角，动物会走来走去）。

- MVP 三只动物：🦊 账本狐狸（消费体检）· 🦜 嘴替鹦鹉（文案嘴替）· 🐱 摸鱼猫（氛围位）。
- 交互：拖文件 / 输入话题 = 投喂派任务；动物走去干活，干完叼着结果回来，顺便互相吐槽。
- 你可以：观察它们、投喂任务、点开某只动物看「内心」档案。

---

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 壳 | **Electron**（main + renderer） | 主进程跑 Agent 引擎，渲染进程跑可视化；托盘 + 通知开箱即用 |
| 前端 | React 18 + Vite + TypeScript | UI 面板、档案卡、设置 |
| 可视化 | **Canvas 2D + requestAnimationFrame** | 游戏循环、俯视地图、精灵移动；抽象好渲染层，可换 PixiJS 上真立绘 |
| Agent 引擎 | **手写状态机**（每只动物一个 loop） | 无框架黑盒，可控、可测 |
| LLM | 抽象 Provider（Mock → DeepSeek / OpenAI 兼容 / Ollama） | 可切、可本地 |
| 存储 | 先 JSON 文件，后 SQLite | 动物/任务/记忆/事件流，单文件本地 |
| 连接器 | 抽象接口（Mock → IMAP / CSV / OCR） | P0 假数据，真接口留好 |

```
┌ 渲染进程 (React + Canvas) ───────────────────────────────┐

│  ├ tasks/     任务 pipeline(账单分析 / 文案生成)             │
│  ├ tools/     工具注册表                                    │
│  ├ memory/    短期 + 长期记忆                               │
│  ├ llm/       provider 抽象 + token 预算管理器(budget)      │
│  ├ connectors/ 数据源抽象(mock / imap / csv)                │
│  └ store/     持久化                                        │
│  托盘 · 系统通知 · 生命周期                                 │
└────────────────────────────────────────────────────────────┘
```

## 4. Agent 引擎（核心设计）

每只动物一个状态机，状态：`idle(睡觉)` / `moving(走动)` / `working(干活)` / `socializing(串门)` / `done(交结果)`。

循环：

```
perceive(读最近事件/任务/其他动物) → plan(人设+记忆 → 决定行为)
  → act(干活/说话/走动) → reflect(睡一觉 → 压缩记忆/更新关系)
```

- **真实任务 = 工具链 pipeline**：
  - 账本狐狸：`ingest → parse → classify → detect → compute → report`
  - 嘴替鹦鹉：`素材 → 选风格 → 生成`
- **可视化由状态机驱动**：`working` → 狐狸走向账本台、账本翻页动画；`done` → 叼卡片回来；`socializing` → 走向另一只动物冒泡。
- **动物联动**：狐狸算完账 → 鹦鹉把报告写成发疯文学 → 猫吐槽，演示多智能体协作。

---

## 5. 时间模型 & Token 控制

- **双层时钟**：渲染层每帧动画（不耗 token）；心智层低频 + 事件驱动（投喂 / 任务到达 / 定时才唤醒 LLM）。
- **分层模型**：任务分析用大模型，社交寒暄用小模型 / 纯模板。
- **粮仓预算**：每日 token 预算 + 每动物配额，超了自动降级省电（少说话、走模板）。

---

## 6. 数据模型

```
animals(id, species, name, personality, state, pos, mood)
tasks(id, animal_id, type, input, status, result, ts)
events(id, animal_id, type, content, ts)      # 事件流 / 公告板
memories(animal_id, kind, summary, ts)         # 长期记忆摘要
relationships(a_id, b_id, valence)             # 好感度
zoo_state(氛围值, 时间, token预算)
```

## 7. 可视化（俯视地图）

- **地图**：俯视 2D 动物园，几个展区（狐狸窝 / 鹦鹉树枝 / 猫窝）+ 空地道路，动物可寻路走动。
- **动物**：emoji/简单精灵起步，走路 = 平移 + 轻微颠簸 + 朝向翻转；后续换真立绘。
- **状态可视化**：🛌 睡觉（空闲）· 📖 埋头啃数据（干活中）· 🏃 走动 · 🎁 叼卡片回来（出结果）· 🚶 串门（社交）。
- **气泡**：动物说话 / 状态文字。
- **面板**：点动物 → 档案卡；顶部 → 粮仓（token 预算）指示 + 氛围值。
- **投喂**：拖文件 / 输入话题 → 派任务给对应动物。

## 8. 分期路线

- **P0（第一个可看版本）**：Electron 壳 + 俯视地图 + 三只动物能走/睡/冒泡 + 假任务跑通（狐狸 mock 账单 → 报告，鹦鹉写发疯文学，猫吐槽）+ 粮仓 UI。
- **P1**：接真 LLM + 真数据（邮箱 IMAP / CSV）。
- **P2**：更多动物、关系演化、定时任务、系统通知（托盘常驻）。
- **P3**：真立绘 / 走路动画、打包分发。

---

## 9. 关键风险（诚实）

1. **可视化工作量最大**（俯视地图 + 寻路 + 状态动画），是 P0 的主耗时。
2. token 成本要边跑边调，预算管理器是硬需求。
3. 真实数据接入（邮箱 / 账单）有兼容性和隐私问题，故 P0 先 mock。
4. Electron 打包体积偏大（可接受，或以后换 Tauri，壳可替换、核心不变）。
